# Контекст Dots/Duet и инструкции проектов

Версия 0.6 добавляет сбор предоставленного снимка контекста и явное включение проектных инструкций в экспортируемую копию навыка. Автоматического чтения аккаунтов Dots или Duet нет. Источниками служат реально доступные инструменты, пользовательские выгрузки, текст настроек и другие предоставленные материалы.

## Почему описание памяти не заменяет весь контекст

Инструкции dot отделены от ChatGPT custom instructions; они могут задавать стиль работы и правила согласования действий конкретного агента. Это нужно учитывать как самостоятельный источник, с областью действия. [Управление dot](https://learn.chatgpt.com/docs/dots/controls).

Собственные заметки dot отделены от ChatGPT saved memory. Кроме них есть порученные обязанности, текущие задачи и регулярная работа. Для расписания существенны задача, время и часовой пояс, условие уведомления и место результата; новый поток работы не получает автоматически всю историю dot. [Задачи и память dot](https://learn.chatgpt.com/docs/dots/tasks-and-memory).

У Claude отдельно описаны инструкции аккаунта, инструкции проекта и навыки. Проектные требования действуют в рамках своего проекта. [Персонализация Claude](https://support.claude.com/en/articles/10185728-understanding-claude-s-personalization-features). Duet использует память, навыки и приложения аккаунта Claude; это не является обещанием API для полной выгрузки этих данных. [Claude Duet](https://claude.com/product/claude-duet).

Официальные страницы проверены 20 ноября 2026. Они определяют различия источников, но не подтверждают доступ конкретной сессии к каждому из них. Скрытые системные инструкции провайдера не являются пользовательским контекстом для экспорта.

## Что учитывает снимок

| Раздел | Что сохраняется при фактической доступности |
| --- | --- |
| Инструкции аккаунта | Пользовательские настройки аккаунта, отдельно от пересказа памяти |
| Инструкции агента | Правила конкретного dot/агента и их исходная область |
| Правила действий | Условия согласования, ограничения и исключения пользователя |
| Сохранённая память | Доступные факты и предпочтения с источником |
| Заметки агента | Отдельно доступные записи о решениях и продолжающейся работе |
| Проекты | Идентичность, цель, статус и существенный контекст |
| Инструкции проектов | Исходный текст правил, проект и область действия |
| Сведения о навыках | Наблюдаемый каталог и зависимости; оригиналы собираются отдельно |
| Порученные обязанности | Ожидаемые результаты и границы постоянной работы |
| Текущие задачи | Следующий шаг, ожидание, связь с проектом и имеющиеся результаты |
| Регулярные задачи | Инструкция, расписание, часовой пояс, триггер, состояние и условие окончания |
| Подключения | Аккаунты, ресурсы и фактически наблюдённые возможности |
| Каналы и места результатов | Куда отправлять результат, кому он доступен и когда нужен сигнал |
| Артефакты | Доступные документы, файлы и связи с работами |
| Диалоги | Выбранный предоставленный контекст разговоров |

Это перечень для агента, а не анкета из 15 вопросов пользователю. Агент использует уже известное, продолжает независимую работу и задаёт только следующее существенное уточнение. Неизвестный часовой пояс, адрес результата или зависимость остаются неизвестными до получения основания.

## Как различаются результаты проверки

- `provided` — есть конкретные данные, источник и основание.
- `pending` — раздел ещё не проверен или данные ещё не предоставлены.
- `unavailable` — есть известная причина недоступности; это не означает отсутствия данных.
- `not_found` — релевантная проверка действительно выполнена и ничего не нашла в проверенном охвате.
- `excluded` — пользователь выбрал не включать этот раздел; решение сохраняется явно.

Пропущенный раздел появляется в отчёте как `pending`. Его отсутствие не превращается в «у пользователя этого нет». Даже если все категории отмечены, `complete_account_export` остаётся `false`: программа проверяет предоставленный снимок, а не весь аккаунт. Флаги охвата опираются на записанные наблюдения, а не на независимый доступ Python к платформе.

## Исполняемая часть

В исходном проекте:

```text
python -m portable_memory context-template --platform dots --source context-source.json --out context-snapshot.json
python -m portable_memory context-collect context-snapshot.json --out collected-context --accept
```

Для Duet используется `--platform duet`. В самостоятельном навыке точка входа — `python scripts/memory_tool.py`. Между командами агент заполняет снимок фактически полученными данными. Самодостаточные поля, допустимые типы и примеры находятся в [инструкции навыка](../skills/memory-export/references/agent-context.md).

Результаты: `memory.json` с неподтверждёнными записями, `assets/context/source.json` со структурно сохранённым исходным снимком и `context-report.json` / `context-report.md`. Текст и значения не пересказываются. Исходное форматирование байтов JSON не сохраняется, поскольку данные сериализуются заново. Пользовательское подтверждение и оценка актуальности выполняются следующим этапом.

Проектная инструкция имеет `kind: rule`, исходный `project_id` и область `project:<project_id>`. При наличии самого проекта создаётся связь с его реальной записью. Если проект отсутствует, он не выдумывается ради связности: пробел остаётся в отчёте. Неизвестные аккаунты и рабочие пространства не объединяются по одному похожему названию.

Ссылка на документ, диалог, навык или подключение не скачивает его оригинал. Описание задачи не запускает работу, а скопированное расписание не создаёт автоматизацию. Все внешние действия требуют реально доступных инструментов принимающего агента и согласованного объёма.

## Когда инструкция проекта входит в навык

Запись «этот навык относится к проекту» в графе памяти не гарантирует, что агент прочитает проектные правила при вызове навыка. Для выбранной зависимости нужны сами тексты правил и ссылки на них в экспортируемом навыке.

Порядок работы:

1. Агент определяет по источникам, какие конкретно инструкции нужны выбранному навыку. Правила всех проектов не добавляются автоматически.
2. Пользовательские проектные инструкции сохраняются без пересказа, с названием, источником и прежней областью действия. Если нужна новая область, согласуется именно это изменение.
3. Программа создаёт новую экспортируемую копию навыка, добавляет файлы правил и ссылки на них из `SKILL.md`. Исходный навык не редактируется; исходный `SKILL.md` также сохраняется внутри копии.
4. Изменённая запись навыка снова становится `pending`. После проверки изменённой копии она экспортируется вместе с обязательными записями проекта, правил и соответствующими файлами.
5. При чтении пакета и импорте проверяется, что связь, содержание и реальные файлы согласованы. Конфликтующее старое правило у получателя нельзя молча подставить вместо нужного нового.

Команда:

```text
python -m portable_memory skill-bind-context reviewed-memory.json --assets selected-assets --bindings bindings.json --out bound-export --accept
```

В `bindings.json` указываются реальные ID записи навыка, записи проекта и выбранных правил из памяти. Проект и правила должны иметь одну явную область `project:`. Исходные ID элементов платформы и ID созданных записей могут отличаться; используются фактически полученные записи, а не угаданные значения.

Результат находится в `bound-export/memory.json`, `bound-export/assets/` и `bound-export/binding-report.json`. В копии навыка появляется `references/portable-context/SKILL.original.md` и отдельные ссылки на выбранные инструкции. Для строк сохраняется исходный текст; структурированные значения представляются как JSON без смыслового пересказа.

Частичный снимок навыка допустим, когда настоящий `SKILL.md` доступен; статус частичности и исключения сохраняются. Недоступные оригиналы нельзя заменить выдуманным навыком. Если после привязки меняется правило, нужно обновить и проверить исходные записи, затем заново создать копию из оригинального комплекта. Старое подтверждение изменённого содержания не восстанавливается копированием хеша.

Проверяется и контрольная сумма всего привязанного комплекта навыка: изменение скрипта или конфигурации также требует новой сборки и проверки. При импорте проверяются все привязанные навыки, остающиеся в объединённой памяти. `--current` передаёт только JSON, а не прежние файлы. Поэтому неполный новый пакет, в котором отсутствуют файлы сохраняемого привязанного навыка, отклоняется до подготовки полного согласованного комплекта. Предыдущее рабочее хранилище при таком отказе не изменяется. Это ограничение текущего способа объединения, а не автоматическое восстановление старых вложений.

В Windows глубина выбранного пути тоже имеет значение. Импорт заранее проверяет ограничение длины путей и при необходимости просит выбрать более короткую папку результатов. Поддержка произвольно длинных Windows-путей не заявляется; при таком сообщении нужно сменить выходную папку, сохранив исходные файлы.

## Граница результата

Файлы и ссылки позволяют переносить проектный контекст вместе с навыком. Они не доказывают совместимость с принимающей платформой, загрузку правил её механизмом навыков или успешное выполнение процесса. Установка, сохранение нативных инструкций, подключение сервисов и восстановление автоматизаций проверяются отдельно. Полная таблица реализованного и зависимого от платформы — [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md).
