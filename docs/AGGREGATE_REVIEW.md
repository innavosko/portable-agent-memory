# Общий профиль из нескольких источников

Перед экспортом программа требует проверку общего набора сведений. Отдельная проверка каждой выгрузки недостаточна: рабочий Codex, личный ChatGPT и проект Claude Code могут по-разному описывать одно правило, дополнять друг друга или содержать противоречие.

Один главный агент ведёт объединение и разговор с пользователем. Это может быть текущий Codex. Другие агенты остаются источниками: они могут подготовить материалы своим навыком, но устанавливать навык во всех трёх местах не обязательно. Достаточно передать главному доступные архивы, тексты, инструкции и выбранные оригинальные файлы. Программа не получает доступ к SaaS-аккаунтам автоматически.

## Путь для трёх источников

1. **Показать известную карту.** «Объединяю рабочий Codex, личный ChatGPT и выбранный проект Claude Code. Уже доступные материалы обработаю сейчас; недоступное отмечу отдельно». Уточнение требуется только там, где неизвестная идентичность или область может привести к ошибочному объединению. Веб и приложение одного аккаунта не считаются разными источниками только из-за интерфейса.
2. **Собрать материалы каждого источника.** Сохранить исходное утверждение, область действия, происхождение, доступность оригиналов и ограничения охвата. Подготовленные записи источника — промежуточный результат. Они не означают, что общий пакет уже готов или вся история аккаунта просмотрена.
3. **Проверить объединение по смыслу.** Главный агент сопоставляет записи, включая разные формулировки и идентификаторы. Отдельный проверяющий или честно обозначенный второй проход той же модели проверяет эти выводы. Python проверяет охват, структуру и соответствие актуальному составу; сам модель не вызывает и смысл не определяет.
4. **Спросить только о необходимом.** Неизменённые действительные подтверждения сохраняются. Подтверждённое правило, найденное ещё в одном источнике с тем же смыслом, не требует нового интервью после проверки эквивалентности. Настоящее изменение, новое противоречие или неизвестная актуальность требуют отдельного решения. Вопросы задаются по одному; отсрочка сохраняется.
5. **Проверить текущую готовность и экспортировать.** Итог должен соответствовать нынешнему набору записей и источников. Добавление источника аннулирует прежнюю общую проверку даже до появления его записей. Когда сведения готовы, главный выпускает общий пакет; принимающий агент затем проверяет файлы и отдельно выполняет доступную настройку.

## Что объединять, а что оставить раздельно

| Наблюдение | Действие |
| --- | --- |
| «Отвечай коротко» и «Предпочитаю лаконичные ответы» в одной области | Проверить эквивалентность; показывать одно правило с источниками и ссылками на исходные записи |
| «Основная рабочая почта — A» и «Основная рабочая почта — B» для одного текущего назначения | Показать противоречие; не выбирать победителя по времени выгрузки |
| Две действующие почты без утверждения об единственной основной | Сохранить обе; это может быть допустимое множество |
| «Отвечай коротко» и «Для проекта X отчёт должен быть подробным» | Сохранить условия и области; проектное правило не делать глобальным |
| Старое правило и его явно подтверждённая историческая версия | Сохранить историю отдельно от действующего поведения |
| Ещё один источник подтверждает прежнее согласованное правило | Обновить общую проверку и происхождение; не повторять вопрос только из-за нового источника |

Эквивалентность не удаляет оригиналы. Общий вид показывает выбранную основную запись, остальные остаются её смысловыми дублями со своими источниками. Изменение области действия, условий или смысла нельзя скрыть под видом дубля.

## Когда источник приходит позже

Пользователю не нужно снова проходить весь профиль. Например: «Пришёл проект Claude Code. Я сверил его с уже согласованным: языковое предпочтение совпадает, правила проекта сохранены отдельно. Осталось одно различие в длительности встреч: это отдельный тип встреч или изменение общего правила?»

Модель использует прежнюю проверку для неизменённого и изучает новые записи вместе с затронутыми смысловыми группами. При этом новый отчёт должен покрывать весь актуальный состав, а не только появившиеся строки: иначе нельзя подтвердить, что между старым и новым нет пропущенного противоречия. Неизменённые решения и отложенные вопросы переносятся; изменившаяся проблема проверяется заново.

Если связана карта сбора, её новые или изменённые источники тоже должны попадать в общую проверку. Карта источников не является доказательством, что содержимое уже получено или прочитано.

## Что делает код и чего он не делает

Общее состояние хранится в одной локальной SQLite вне синхронизируемой папки. Назначенный главный агент выполняет изменения с текущей ревизией. Это защита последовательности работы, а не подтверждение личности оператора или синхронизация независимых облачных чатов.

Код связывает общую смысловую проверку с актуальными записями и картой источников, требует второй проход и не допускает обычный экспорт в обход этого этапа. Отдельные команды подтверждения записи или проверки профиля остаются полезными промежуточными действиями, но не заменяют общую готовность.

Если пользователь явно выбрал частичный перенос, недоступные источники и отложенные сведения могут остаться в составе с соответствующим статусом. Общая смысловая проверка всё равно обязательна. Неразрешённое противоречие не переносится как действующее правило: конфликтующие активные варианты понижаются до непроверенных. Частичный пакет нельзя называть полной готовностью.

Старый пакет без результата общей проверки не считается готовым импортом этой версии. Его явно предоставленные JSON и исходные файлы можно использовать для новой подготовки. Встроенная автоматическая конвертация старого пакета не заявляется; подставлять недостающий отчёт проверки нельзя.

У получателя может уже быть своя память. Если после объединения получился другой набор сведений, входящая проверка не становится проверкой этого нового набора. Программа сохраняет файлы и действительные решения пользователя, но отмечает необходимость общей сверки и удерживает применение активного профиля. Главный агент проверяет получившееся объединение по смыслу и выпускает новый общий пакет; неизменённые ответы пользователя сохраняются. Python обнаруживает несовпадение проверенного состава, а смысл снова проверяет модель или человек.

Главный агент получает смысловые решения от модели или человека. Указание имени проверяющего — правдивое заявление исполнителя, а не независимая проверка личности или гарантия правильности. Дата выгрузки не доказывает, что каждое утверждение в ней актуально. Недоступный источник не считается пустым.

Рабочая инструкция и точные команды находятся в `references/common-profile.md` обоих самостоятельных навыков. Проверка отдельного утверждения по источнику описана в [PROFILE_REVIEW.md](PROFILE_REVIEW.md). Готовый переносимый пакет не означает, что память, навыки, подключения или расписания уже применены в принимающем SaaS.
