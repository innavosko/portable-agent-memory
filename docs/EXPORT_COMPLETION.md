# Завершение экспорта — 0.8.4

Упаковщик заканчивает работу конкретным комплектом для выбранного получателя: реальные файлы данных, необходимые инструкции или установщик импорта и `NEXT_STEPS.md`. В инструкции указаны имена файлов, следующий шаг пользователя и готовое сообщение для запуска импорта. Для обычного ГигаАгента всегда создаются **полный пакет выбранного контекста для пользователя** и **отдельная папка Markdown для загрузки**. В неё не помещается полный ZIP; загружаются только инструкция импорта и адаптированный профиль. Для остальных получателей рядом создаётся `handoff-manifest.json` с составом и контрольными суммами.

Это завершение экспорта и подготовка к передаче, а не подтверждение записи памяти в другом аккаунте. Код не подключается к ChatGPT, Claude, ГигаАгенту или ГигаАгенту Про, не устанавливает навыки и не вызывает их инструменты памяти.

**До создания итоговых файлов для ГигаАгента агент показывает в чате:** что войдёт в память; что не войдёт, почему и где сохранено; чего не хватает и что нужно уточнить. Смешанные записи сначала разделяются по смыслу: временная задача не должна унести с собой подтверждённое предпочтение или правило проекта. Источники и каждый результат проходят повторную содержательную проверку. Уже согласованные сведения не требуют нового общего опроса. [Как адаптируется профиль](GIGA_ADAPTATION.md).

**Обязательный финальный ответ при экспорте для ГигаАгента:** ссылка на полный выбранный ZIP с пометкой **«Сохранить себе; не загружать в ГигаАгент»**, затем два отдельных вложения — `client-memory-export.md` и `import-instruction.md` — с пометкой **«Загрузить в ГигаАгент»**, и готовое сообщение для запуска импорта прямо в том же ответе. Агент выдаёт всё это сам, без дополнительной просьбы пользователя. Если интерфейс показывает вложения ссылками, на каждый файл нужна отдельная проверенная ссылка скачивания. Ссылка на папку и памятка `NEXT_STEPS.md` не заменяют выдачу файлов. Пока файлы недоступны пользователю, передача не завершена.

Код возвращает три пути в `user_delivery_files` и только два MD в `gigaagent_upload_files`. Статус `local_files_prepared` означает, что файлы созданы, а не прикреплены к чату. Выдачу выполняет агент средствами своего чата; её ещё нужно проверить в реальных веб-аккаунтах. Если прикрепление или скачивание недоступно, агент сообщает, какие файлы не переданы, и предлагает способ сохранения без заявления о завершении.

## Что получает пользователь

| Получатель | Комплект и действие |
| --- | --- |
| ChatGPT | Файлы выгрузки и отдельный `memory-import.zip`. Установить импортный навык через доступный канал, приложить выгрузку и отправить готовое сообщение. Обычный веб-чат не устанавливает навык от одного прикрепления ZIP. |
| Claude | Файлы выгрузки и `memory-import.zip`. При доступной функции: **Customize → Skills → + → Create skill → Upload a skill**, с включённым выполнением кода. После установки приложить выгрузку и запросить импорт. |
| ГигаАгент Про (Ouroboros) | Выбранные файлы. По маршруту, указанному пользователем: **Меню → Amberkeep carry memory**, установка/включение и запрос импорта. Этот путь не проверен в живом аккаунте; приём файлов не означает, что память записана. |
| ГигаАгент | Сохранить себе полный ZIP. В ГигаАгент загрузить только `import-instruction.md` и реальный `client-memory-export.md` по заданному формату. Готовые записи относятся к `user`, `feedback`, `project`, `reference` и соблюдают ограничения памяти. Архивы и навыки ГигаАгент не принимает; распаковка и установка не предлагаются. |

Для ChatGPT самостоятельная установка навыков предусмотрена в поддерживаемых средах desktop/CLI/IDE; веб использует канал плагинов. Комплект не доказывает наличие подходящего веб-плагина. Если установки нет, передайте полный импортный ZIP или всю извлечённую папку с инструкциями, справочниками и кодом в среду, где доступны файлы и выполнение кода. Это разовый запуск, не постоянная установка. Один `SKILL.md` недостаточен. [Каналы OpenAI](https://learn.chatgpt.com/docs/build-skills) · [Навыки Claude](https://support.claude.com/en/articles/12512180-use-skills-in-claude).

Для ГигаАгента инструкция требует прочитать все совместимые Markdown профиля и проверить их вместе с текущей памятью. Она ограничивает импорт готовым разделом, проверяет смысловые повторы, противоречия, ёмкость и версии существующих записей. После `memory_save` результат проверяется через `memory_read`. Без реальных инструментов памяти импорт не объявляется выполненным. `NEXT_STEPS.md` читает пользователь; этот файл не прикладывается к импорту. Отчёты, навыки, исходные переписки и резервные материалы хранятся вне папки передачи ГигаАгенту. Если есть только архив, отправитель должен подготовить профиль Markdown; переименование архива или JSON не подходит. Подробности — в [профиле получателя](../skills/memory-import/references/recipient-profiles.md).

Установочных навыков по-прежнему два: `memory-export` и `memory-import`. Копия импортного установщика внутри экспортного комплекта предназначена для передачи получателю и не включает второй навык автоматически. Установочные ZIP не содержат личный профиль пользователя.

## Команды для разработчика

Команды ниже запускаются из корня проекта. Они используют уже проверенный общий профиль; новый комплект передачи не обходит общую проверку. Для выходных папок нужны новые пути. Список получателей: `python -m portable_memory recipient-options`. Внутри установленного навыка вместо `python -m portable_memory` используется `python scripts/memory_tool.py`. Канонические идентификаторы основных маршрутов: `chatgpt`, `claude`, `gigaagent`, `gigaagent_pro`.

### Обычный экспорт

```text
python -m portable_memory export common-memory.json --common-store common.sqlite --out reviewed-memory.zip --target claude --handoff-out ready-for-claude
```

`--target` выбирает получателя; без него используется `other`. `--handoff-out` задаёт папку с реальными файлами и инструкциями. Без этого аргумента используется имя выходного файла с окончанием `-import`, например `reviewed-memory-import/`. Для ChatGPT/Claude нужен собранный импортный установщик: из репозитория он берётся из `skills/memory-export/assets/memory-import.zip`, из установленного навыка — из его `assets/`. Сборщик размещает там полный установщик. Другой путь можно задать через `--import-skill dist/memory-import.zip`. Если нужного файла нет, подготовка завершается ошибкой, а не обещанием отсутствующего ZIP.

Для обычного ГигаАгента эта команда не подходит: используйте его проверенную Markdown-проекцию.

### Экспорт для ГигаАгента

После разделения смыслов и проверки проекции создайте предварительный обзор:

```text
python -m portable_memory giga-preview --memory common-memory.json --common-store common.sqlite --projection giga-projection.json --out giga-preview.json
```

Результат команды содержит `output`, `preview` и `native_memory_applied: false`. Сохранённый JSON — сам объект обзора. **Агент должен показать `preview.markdown` в чате до команды экспорта**, дополнить его известными пробелами и фактическими местами сохранения исключений. Создание JSON не доказывает показ пользователю. Уточняются только неразрешённые существенные вопросы; повторное согласование всего профиля не требуется. При изменениях обновляются содержательная проверка и обзор.

```text
python -m portable_memory giga-export --memory common-memory.json --common-store common.sqlite --projection giga-projection.json --preview giga-preview.json --out client-memory-export.md --report giga-export-report.json --full-out selected-context-full.zip --assets selected-assets --handoff-out ready-for-gigaagent
```

Проекция предварительно проходит содержательную проверку, описанную в [recipient-profiles.md](../skills/memory-export/references/recipient-profiles.md). Соответствующий текущему содержимому `--preview` обязателен: отсутствующий, изменённый или устаревший обзор не подходит. Это проверка согласованности файлов, а не доказательство пользовательского согласия. Команда создаёт полный переносимый пакет из текущего общего профиля и выбранных файлов `--assets`, затем дополнительную копию профиля для ГигаАгента, `import-instruction.md` и пользовательский `NEXT_STEPS.md`. Полный пакет не строится из сокращённой проекции. `--full-out` меняет его имя; без аргумента используется `<имя-профиля>-full.zip`, например `client-memory-export-full.zip`. Состав исходников задаётся явно: либо `--assets selected-assets`, либо `--no-assets --asset-scope-note "Фактический состав профиля и причина отсутствия исходников"`. Для `--no-assets` пояснение обязательно; выбранные доступные файлы нельзя тихо пропустить. Агент использует прежние решения пользователя, а не начинает повторный опрос. При `--assets` пояснение необязательно и может описывать известные пробелы. Полные записи, исторический и отложенный контекст сохраняют статусы; записи, исключённые пользователем, не включаются. Включённый исходный архив не очищается от исключённых фрагментов автоматически: агент должен проверить выбранные оригиналы отдельно. Поле `full_package` возвращает фактический путь, контрольную сумму и состав; полнота относится к выбранным и предоставленным данным, а не ко всему аккаунту. В папку файлов для загрузки в ГигаАгент манифест не записывается (в полном ZIP он есть): в результате команды `manifest: null`, контрольные суммы возвращаются отдельно. Поле `upload_files` перечисляет только инструкцию и профиль — их и загружают в ГигаАгент. Если `--handoff-out` не задан, создаётся `client-memory-export-import/`. Создание файла не является импортом в память ГигаАгента.

### Комплект передачи из существующих файлов

```text
python -m portable_memory handoff-prepare --target gigaagent --files client-memory-export.md --instruction skills/memory-export/assets/import-instruction.md --out ready-for-gigaagent
python -m portable_memory handoff-prepare --target chatgpt --files reviewed-memory.zip --import-skill dist/memory-import.zip --out ready-for-chatgpt
python -m portable_memory handoff-prepare --target gigaagent_pro --files reviewed-memory.zip --out ready-for-gigaagent-pro
```

Выберите одну подходящую команду. `--files` принимает один или несколько существующих файлов; для `gigaagent` допустимы только профили Markdown по полной структуре заданного формата. `--instruction` указывает проверенную инструкцию ГигаАгента; `--import-skill` — полный установщик `memory-import` для другого поддерживаемого получателя, не для ГигаАгента. Без этих двух аргументов используются соответствующие ресурсы поставки. Файлы проверяются и копируются; инструкция перечисляет фактически переданные имена. Команда не создаёт профиль из пустого шаблона, не выполняет семантическую проверку вместо агента и не загружает файлы в облако.

`handoff-prepare` собирает передачу из уже подготовленных файлов. Она не создаёт полный выбранный пакет и не завершает двойной экспорт для ГигаАгента. Используйте `giga-export`, затем проверьте обе части результата. Прямая упаковка Markdown не заменяет показ предварительного обзора или общую проверку.

## Проверка результата

Проверьте получателя, состав и содержимое `NEXT_STEPS.md`, наличие каждого названного файла и доступность результата в выбранной пользователем папке. Создание файла в синхронизируемой папке на компьютере само по себе не подтверждает загрузку на Google Диск, Яндекс Диск или другое выбранное хранилище.

Получатель начинает по сообщению пользователя. Он отдельно сообщает, что прочитано, что действительно сохранено или установлено, что проверено чтением и что осталось выполнить. Созданный ZIP, пересказ в чате и готовая папка не заменяют такой отчёт.
