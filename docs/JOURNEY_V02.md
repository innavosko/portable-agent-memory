# Пользовательский путь версии 0.2

Навык помогает собрать память из нескольких мест, не превращая начало работы в анкету. Агент использует уже известные сведения, показывает короткий план, уточняет только то, что мешает следующему действию, и продолжает независимую работу во время ожидания.

Уточнение 0.3: сбор заканчивается промежуточным результатом; конечная цель — [настройка принимающего агента под ключ](PRODUCT_GOAL.md). Основной маршрут доставки — [пользователь копирует папку между дисками и запускает приём](CLOUD_DELIVERY.md). Реализация почтового наблюдения и фонового ожидания отложена; описанные ниже возможности относятся к последующему интеграционному этапу.

## 1. Начать с того, что уже известно

Прочитать текущую просьбу, переданные файлы и имеющееся состояние переноса. Не спрашивать повторно выбранный объём, известные аккаунты, назначенного наблюдателя или подтверждённые факты профиля. Если новый материал им противоречит, показать конкретное расхождение.

Пользователь может начать с любого этапа: «найди важные работы», «вот архив», «хочу всё перенести», «принимай готовый пакет». Для подбора работ не нужны заранее выбранный диск, подключение почты или получатель. Для готового пакета не нужен повторный сбор исходной истории.

## 2. Показать предложенную карту источников

Карта строится из наблюдений и уточняется по мере работы. Для источника важны сервис, аккаунт, рабочее пространство, вид данных и конкретный проект или ресурс. Браузер и приложение — способы доступа, а не автоматически разные наборы данных.

Пример сообщения, когда это следует из слов пользователя:

> Вижу четыре группы материалов: чаты ChatGPT, чаты Claude, проекты Claude Code и проекты Codex. Браузер и приложение пока отмечаю как способы доступа. Уже загруженный архив можно разобрать сейчас; для проектных папок позже понадобится выбрать нужные материалы.

Если совпадение аккаунтов неизвестно, не объединять истории молча. Пометить предполагаемое совпадение и задать один вопрос, ответ на который сильнее всего влияет на следующий шаг. Например:

> В ChatGPT в браузере и приложении у вас один аккаунт? Это поможет не запросить один архив дважды.

Не требовать сразу перечислить все адреса, папки, интеграции и приложения. Неизвестный источник можно оставить на потом; это не блокирует работу с уже предоставленными материалами. Предложенная карта не считается согласием читать всё перечисленное.

## 3. Согласовать ближайший полезный шаг

Предложить разумный следующий шаг на основе запроса: например, разобрать уже загруженный архив и подготовить список работ. Если пользователь уже поручил это, выполнять без повторного подтверждения.

Отдельный выбор нужен там, где остаётся существенная неоднозначность: какой аккаунт, какой проект, куда отправить результат, включать ли исходную переписку. Объяснить причину вопроса одной фразой. Дать возможность пропустить источник, вернуться позже или передать данные вручную. Не считать молчание выбором предложенного варианта.

Один свободный ответ пользователя может закрыть несколько вопросов: например, «этот аккаунт рабочий, архив ещё готовится, пока берём только профиль». Агент фиксирует все понятные решения без трёх дополнительных подтверждений. После фактического показа вопроса сохраняется событие `question_shown`; следующее представление отмечает `awaiting_answer` и не предлагает задавать тот же вопрос заново. Нельзя помечать вопрос показанным заранее или после неудачной попытки показать его. Ожидание ответа не останавливает независимые задания.

## 4. Готовить независимые части параллельно

Пока один архив готовится, агент может обрабатывать уже предоставленные файлы, собирать доступные правила, составлять кандидатов в важные работы и проверять принимающую среду. Не нужно ждать самого медленного источника, чтобы показать первый полезный результат.

Пример:

> Архив Claude ещё готовится. Пока разберу загруженный ChatGPT и предложу работы для сохранения. К Claude вернёмся, когда появится файл.

В версии 0.2 программный сборщик действительно может параллельно обрабатывать независимые задания по предоставленным путям: архив, структурированную память или выбранную папку. Это обработка файлов в доступной среде, а не одновременный вход во все SaaS-аккаунты. Ссылка на письмо или название папки на Google Drive не заменяют полученный файл.

## 5. Подключать почту и диск по необходимости

Сначала проверить, есть ли подходящий инструмент и доступ к нужному ресурсу. Если подключение уже работает, не предлагать установить его заново. Если нужно ждать письмо, объяснить пользу подключения именно сейчас и предложить ручной вариант.

Оба агента могут быть подготовлены заранее. Один согласованный агент следит за поступлением; второй проверяет собственный доступ и готовность принять результат. Повторная проверка получателя нужна: доступ отправителя не гарантирует доступ получателя. Второй независимый наблюдатель и повторное уведомление обычно не нужны.

Проверка в текущей сессии не означает непрерывного наблюдения. Фоновое ожидание возможно только через реально доступный и успешно созданный механизм среды. Почтовое уведомление о готовности не означает, что архив скачан. Файл в папке не означает, что его содержание проверено.

## 6. Держать единое состояние процесса

Локальное состояние версии 0.2 хранится в одной базе SQLite вне синхронизируемых папок, например OneDrive. Она позволяет согласовывать версии изменений и захватывать задания между исполнителями, которые действительно используют эту же базу. Рабочую базу нельзя синхронизировать облачным диском как обычный документ; это не механизм облачного согласования аккаунтов.

JSON состояния нужен для передачи и возобновления. Он не включает собранные файлы: их передают отдельно, после возобновления проверяют доступность результатов. `migration-resume` создаёт новую авторитетную копию в выбранной среде. Перед передачей нужно согласовать, кто продолжает процесс, и остановить работу прежнего владельца над переданными заданиями. Две независимые копии в двух веб-агентах не получают общую блокировку и не объединяют изменения сами.

Если получить актуальное состояние невозможно, честно обозначить неопределённость и предложить безопасный следующий шаг. Не обещать единственное уведомление во всём мире на основании локального журнала событий.

## 7. Показывать результат понятными этапами

Вместо технического списка состояний объяснять, что уже произошло и чего ждём. Различать:

| Этап | Что он означает |
| --- | --- |
| Источник найден | Известно, откуда можно получить данные; содержимое ещё может быть недоступно |
| Файл получен | Реальный файл доступен обработчику |
| Задание выполнено | Код обработал этот файл и создал проверяемый результат |
| Сведения проверены | Пользователь подтвердил содержание и актуальность соответствующих записей |
| Пакет подготовлен | Выбранные материалы собраны и проверены |
| Пакет получен вторым агентом | Получатель действительно прочитал и проверил пакет |
| Применение проверено | Подтверждён результат конкретной операции в принимающей среде |

Завершение заданий сбора не означает завершение миграции. Создание переносимой папки не означает запись в постоянную память SaaS, установку навыков или восстановление интеграций.

## 8. Сохранить проверку содержания удобной

Показывать профиль блоками, а работы — короткими карточками с источниками и причиной рекомендации. Уже подтверждённые неизменённые записи переносить без повторного полного интервью. Уточнять новые сведения, изменённое содержание, противоречия и неизвестную актуальность.

Для работ отдельно выбирать контекст, оригиналы и повторяемые навыки; варианты сочетаются. Не превращать каждый разговор в навык. Подробная логика остаётся в [выборе важных работ и создании навыков](WORKS_AND_SKILLS.md).

## Что проверять в диалоге

- Пользователь уже назвал аккаунт и передал файл: агент не начинает с анкеты.
- Один аккаунт открыт в браузере и приложении: архив не запрашивается повторно.
- Совпадение аккаунтов неизвестно: агент не скрывает предположение, задаёт один полезный вопрос.
- Один источник ожидается: предоставленные независимые материалы продолжают обрабатываться.
- Пользователь не хочет подключать почту: доступен ручной путь, остальные этапы продолжаются.
- Получатель видит пакет, но не умеет сохранять постоянную память: результат обозначен точно.
- Передана копия состояния: два агента не обещают согласованную параллельную работу без общего хранилища.

## Команды состояния

Агент выполняет их в доступной среде Python. Пользователю не нужно вводить команды вручную:

```text
python scripts/memory_tool.py migration-create --config migration-config.json --store migration.sqlite
python scripts/memory_tool.py migration-view --store migration.sqlite
python scripts/memory_tool.py migration-event --store migration.sqlite --event event.json --revision 0
python scripts/memory_tool.py migration-collect --store migration.sqlite --out collected --workers 3
python scripts/memory_tool.py migration-export-state --store migration.sqlite --out migration-state.json
python scripts/memory_tool.py migration-resume --state migration-state.json --store resumed.sqlite
```

Номер версии берётся из последнего состояния, а не из примера выше. Данные события должны соответствовать поддерживаемому действию и фактическому результату. Машинное представление возвращает сводку, источники, задания, доступные действия, ограничения и не более одного следующего вопроса с объяснением. Оно помогает агенту выбрать следующий шаг; его можно изложить естественным языком, сохраняя ограничения.

Пример конфигурации проекта: `examples/migration.json`; пробный запуск на вымышленных данных: `scripts/demo_migration.py`. Каждый самостоятельный навык содержит собственный `references/migration.example.json`: семь вымышленных наблюдений сводятся к четырём источникам, файловые входы отсутствуют. Это пример структуры, а не сведения о реальном пользователе и не согласие на обработку его данных.

Когда файл действительно получен, событие `provide_input` добавляет его путь и основание принадлежности источнику. `wait` фиксирует ожидание, `defer` — решение отложить. Они не запускают наблюдение за почтой. Подтверждённые ответы сохраняются в состоянии, поэтому вопрос о том же выборе не должен появляться снова без новой причины. Старые карточки отдельных передач могут служить источником уже известных фактов, но не заменяют снимок процесса версии 0.2 для команды возобновления.
