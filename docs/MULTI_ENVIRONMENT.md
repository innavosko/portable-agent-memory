# Пользователь с ChatGPT, Claude, Claude Code и Codex

Дата: 20 ноября 2026. Статус: карта источников, управление заданиями и сбор предоставленных файлов реализованы в ядре 0.2.0. Прямое чтение всех видов локальной истории и постоянная облачная синхронизация остаются дальнейшим развитием. Личные аккаунты и папки пользователя при подготовке этого документа не обследовались.

## Основной принцип

У пользователя один согласованный перенос с несколькими источниками. Количество приложений не определяет количество независимых наборов данных.

Различаем:

- **Аккаунт и рабочее пространство:** чьи данные и какие правила доступа действуют.
- **Среду:** браузер, приложение, терминал, редактор, локальный компьютер или удалённое выполнение.
- **Набор данных:** история, профиль, проектные материалы, инструкции, навыки, результаты.
- **Конкретную версию:** снимок архива, версия файла, ветка проекта или изменённый навык.

Один набор может быть доступен через несколько интерфейсов. Один интерфейс может показывать данные разных наборов и режимов выполнения.

## Что проверяем по продуктам

| Среда пользователя | Как учитываем в переносе |
| --- | --- |
| ChatGPT в браузере и приложении | Сначала проверяем совпадение аккаунта, пространства и разговоров. Обычные чаты синхронизируются между вебом и приложением; второй интерфейс сам по себе не требует второго экспорта. |
| Claude Chat в браузере и приложении | Экспорт относится к данным аккаунта и запрашивается из веба или Desktop. При совпадении аккаунта и набора рассматриваем их как один источник, сверяя фактический состав. |
| Claude Code | Дополнительно проверяем выбранные проекты, пользовательские и проектные инструкции, auto memory, навыки, результаты и доступные сессии. Локальные и облачные места выполнения различаются. |
| Codex | Его история отделена от истории ChatGPT. Дополнительно учитываем выбранные папки, инструкции AGENTS.md, навыки и результаты; локальные задачи, worktree и облачные задачи могут иметь разные рабочие файлы. |
| Общая папка или репозиторий | Если оба кодовых агента работали с одними материалами, учитываем проект один раз, сохраняя происхождение и версии. Разные ветки или несохранённые изменения не удаляем как дубли автоматически. |

Основания: [ChatGPT Work и Codex](https://help.openai.com/en/articles/20001275-chatgpt-work-and-codex), [экспорт Claude](https://support.claude.com/en/articles/9450526-export-your-claude-data), [память Claude Code](https://code.claude.com/docs/en/memory), [среды Codex](https://learn.chatgpt.com/docs/environments/modes), [инструкции AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md).

Важные исключения:

- Видимость сессии Claude Code через Remote Control не создаёт новую независимую сессию. При переносе в облако состав передаваемого разговора и файлов нужно проверять отдельно. [Claude Code Desktop](https://code.claude.com/docs/en/desktop).
- Аккаунтные навыки Claude могут загружаться в Claude Code при поддерживаемой версии и способе входа. Локальная копия не обязательно новый навык; локальные изменения не отправляются в аккаунт автоматически. [Навыки Claude Code](https://code.claude.com/docs/en/skills).
- Актуальный просмотрщик экспорта OpenAI предусматривает разделы ChatGPT, Codex и файлов. Это не доказывает, что конкретный архив содержит все локальные проекты и всю историю каждого окружения; сначала читаем состав. [Экспорт OpenAI](https://help.openai.com/en/articles/7260999-exporting-your-chatgpt-history-and-data).
- Экспорт Claude не включает оригиналы загруженных файлов; их получение — отдельная задача. Он также не является документированным полным снимком локальных папок Claude Code. [Состав экспорта Claude](https://support.claude.com/en/articles/9450526-export-your-claude-data).

## Пользовательский путь

### 1. Один короткий входной разговор

Агент выясняет результат: разовый перенос в нового агента или дальнейшая работа с общей памятью в нескольких агентах. Затем уточняет продукты, аккаунты/пространства и наличие важных локальных проектов. Уже известные ответы повторно не запрашиваются.

Под словом «десктоп» уточняется фактический режим только тогда, когда это влияет на сбор: обычный чат, кодовая сессия, локальное либо облачное выполнение. Пользователю не нужно самостоятельно составлять техническую схему хранения.

### 2. Карта источников и охвата

Агент предлагает понятный перечень: облачная история ChatGPT; облачные данные Claude; выбранные локальные проекты; дополнительные сессии и навыки, которых нет в этих источниках. Каждому присваиваются собственный идентификатор, аккаунт/пространство, место хранения, доступные способы чтения, выбранный состав, дата снимка и состояние проверки.

Совпадение адреса почты или названия проекта недостаточно для объединения. Совпадение интерфейсов не доказывает совпадение данных. Отсутствие доступа не означает отсутствие источника.

### 3. Распределение сбора

Один координатор ведёт общий процесс и задаёт пользователю вопросы. Сбор могут выполнять несколько помощников в доступных средах. Если один локальный помощник имеет доступ к выбранным папкам обоих инструментов, второй сборщик тех же папок не нужен.

У каждого архива или снимка проекта своё задание и один ответственный. Два разных архива могут ожидаться параллельно; одно и то же письмо или один снимок не скачиваются повторно без необходимости.

Приоритет веба сохраняется: основной диалог можно вести в веб-агенте. Локальный этап подключается для выбранных материалов на компьютере, когда к ним нет другого подтверждённого доступа. Устанавливать навык во все интерфейсы автоматически не требуется.

### 4. Объединение и проверка

Сначала сопоставляем одинаковые объекты по исходным идентификаторам, происхождению и содержимому. Одинаковые данные сохраняем один раз с перечнем источников. Изменённые версии и противоречия показываем пользователю. Более поздняя дата сообщения сама по себе не делает его содержание правильным.

Личное и рабочее сохраняются в отдельных областях; их объединение — отдельный выбор пользователя. Проектная инструкция остаётся проектной. Настройка конкретного компьютера не становится универсальным предпочтением человека.

После сбора пользователь видит один объединённый профиль и один список работ. Повторно проверяются новые сведения и конфликты, а не каждый раз весь профиль.

### 5. Подготовка результата для получателя

Переносимая память хранится в общем формате, но способ её применения зависит от получателя. Отдельно проверяются постоянная память, файлы проектов, установка навыков и подключения.

Навык, использующий локальный путь или команду конкретной ОС, требует проверки в другой среде. Для веб-агента может понадобиться другой способ получения файла или инструмент. Исходный вариант сохраняется, изменения и непроверенные зависимости обозначаются; полная совместимость не обещается по одному наличию SKILL.md.

### 6. Продолжение работы

Профиль можно передать раньше ожидаемых архивов. Позднее добавляются новые данные с устойчивыми идентификаторами и повторным сравнением.

Если пользователь продолжает пользоваться всеми агентами, нужен отдельный режим обновлений: где хранится подтверждённая версия, кто предлагает изменения, как разрешаются конфликты и что распространяется между личными и рабочими областями. Разовый экспорт сам по себе не обеспечивает общую актуальную память.

## Реализация и дальнейшее развитие

В версии 0.2 пункты 1 и 2 реализованы для предоставленных файлов через один локальный координатор. Для пункта 4 добавлен сбор выбранных папок с перечнем состава, исключениями и проверкой снимка; специализированного чтения всех форматов сессий Claude Code/Codex пока нет. См. [актуальный пользовательский путь](JOURNEY_V02.md). Смысловое сопоставление работ из разных историй выполняет агент с проверкой пользователя; карта источников сама не распознаёт похожие идеи или разные ID одной сущности.

1. **Реестр источников и областей.** Аккаунт, пространство, набор данных, среды доступа, источник происхождения и снимок. Выбранные источники не должны теряться между разговорами.
2. **Общий процесс с отдельными заданиями.** Единый идентификатор переноса, задания по архивам/проектам, ответственные, готовые части, ожидание и возобновление.
3. **Сопоставление объектов между источниками.** Подтверждённые соответствия проектов, версий файлов и навыков; сохранение всех источников и отсутствие молчаливого затирания.
4. **Сбор выбранных локальных материалов.** Инструкции, память, навыки, результаты и поддерживаемые форматы сессий. Сначала предварительный перечень и выбранные папки; наличие приложения не означает доступ ко всем его данным.
5. **Проверка применимости у получателя.** Установлено, доступно как файл, требует подключения, не поддерживается, не проверено — по каждому компоненту.

Текущая версия проверяет записи и пакеты, сравнивает подготовленные данные, ведёт карточку передачи и общий процесс сбора. Автоматического доступа ко всем перечисленным средам и постоянной синхронизации между ними нет.

## Приёмочные случаи следующей итерации

- Один чат открыт на двух устройствах: один объект, а не два экспорта.
- Одинаковая почта используется в личном и рабочем пространстве: области сохраняются.
- Один репозиторий открыт в Claude Code и Codex: общие файлы не дублируются, разные версии не теряются.
- Навык загружен из аккаунта в локальную среду, затем локально изменён: это связь версий, а не автоматическое совпадение.
- Разговор виден удалённо, но компьютер недоступен: доступ к файлам не объявляется успешным.
- Один источник не поддерживается: остальные части продолжают работу, а отчёт остаётся неполным.
- Обновлённый пакет повторно импортируется: неизменённые записи пропускаются, новые и конфликтующие обсуждаются.
- Пользователь хочет продолжать пользоваться всеми агентами: режим обновлений не подменяется обещанием разового переноса.
