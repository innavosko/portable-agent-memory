# Где подготовить и получить пакет памяти

Место отправителя и место получателя выбираются отдельно. Можно сохранить пакет в Google Drive, скачать его и передать через Яндекс Диск, другое облако или файл в чате. Пользователю не обязательно подключать один и тот же сервис к обоим агентам.

Подготовку и проверку пакета можно продолжать, пока место получения ещё не выбрано или доступ к облаку не подтверждён. Сам выбор хранилища не устанавливает подключение и не переносит авторизацию.

## Два способа передачи

**Пользователь копирует пакет.** Отправитель готовит файл; пользователь скачивает его или сохраняет доступным способом, затем передаёт получателю. Хранилища могут совпадать или различаться. Если агент не умеет работать с выбранным облаком, остаётся ручное скачивание и загрузка. Готовность этого маршрута означает только согласованный способ передачи, а не уже выполненное копирование.

**Одна общая папка.** Такой вариант выбирается после двух отдельных проверок: отправитель действительно может записать файл в выбранную папку, а получатель — прочитать его оттуда. Название сервиса, похожие названия папок и даже один провайдер этого не доказывают. При недостатке сведений можно продолжить подготовку пакета и использовать ручной способ.

## Варианты хранилищ

Официальные страницы проверены 20 ноября 2026. Это справочник мест хранения, а не перечень установленных или гарантированно доступных коннекторов. Наличие конкретных инструментов проверяется в той среде, где работает агент.

| Вариант | Официальная страница | Что означает выбор |
| --- | --- | --- |
| Google Drive | [Google Drive](https://www.google.com/intx/en/drive/) | Место для файлов; доступ агента проверяется отдельно |
| Яндекс Диск | [Справка Яндекс Диска](https://yandex.ru/support/yandex-360/customers/disk/web/ru/) | Можно выбрать для сохранения или получения пакета |
| Облако Mail | [Облако Mail](https://cloud.mail.ru/) | Хранилище файлов; подключённая почта не означает доступ к облаку |
| Диск на sberdisk.ru | [Официальный сайт](https://sberdisk.ru/), [справка](https://sberdisk.ru/faq/web) | Конкретный сервис хранения; доступ каждого агента проверяется самостоятельно |
| OneDrive | [Microsoft OneDrive](https://www.microsoft.com/en-us/microsoft-365/onedrive/online-cloud-storage) | Место хранения, с отдельными правами отправителя и получателя |
| Dropbox | [Dropbox](https://www.dropbox.com/features/cloud-storage) | Место хранения и передачи файлов |
| Другое хранилище | Название уточняется у пользователя | Сохраняем фактическое название, не придумываем возможности сервиса |
| Папка на компьютере | Не облачный сервис | Файлы должны быть доступны в текущей среде выполнения |
| Файл в чате | Не отдельное облако | Пользователь скачивает пакет и загружает его в чат получателя |

Если пользователь говорит «Рамблер», нужно уточнить, какой именно сервис и какие файлы он имеет в виду. Код не приравнивает почту Рамблер к хранилищу и не заменяет это название на Диск с sberdisk.ru. До уточнения используется вариант «Другое хранилище» с указанным пользователем названием и неизвестным доступом.

## Что сохраняет программа

`storage.py` сохраняет выбор мест и результат проверки прав, но не выполняет вход, копирование, загрузку или создание общей папки. Подтверждение доступа приходит от реально выполненного инструмента в текущей среде. Официальная страница сервиса не является таким подтверждением.

Для разработчика: местоположение содержит `provider`, `label`, `resource_id`, `access`, `capabilities` и `evidence`. Неуказанные права равны `false`; по умолчанию доступ `unknown`. `manual` означает, что передачу выполняет пользователь, а не что агент получил права.

У проверенного ресурса используется внутренний идентификатор вида `namespace::account-or-owner::resource`, например `google_drive::account-123::folder-456`. Идентификатор включает владельца или пространство имён аккаунта, чтобы одинаковые короткие ID разных аккаунтов не смешивались. Это вымышленный пример структуры, не готовый адрес пользователя. Для общей папки оба агента указывают один и тот же ресурс владельца, даже если сами вошли под разными аккаунтами. Для локальной папки namespace — `filesystem`, для файлов чата — `chat`.

В этих метаданных не хранят пароли, токены и подписанные ссылки. Код отклоняет распознаваемые секреты и ссылки с параметрами; это не полная проверка произвольного текста. Достаточно понятной метки, стабильного ID и описания фактической проверки доступа без секретов.

Пример ручной передачи между разными сервисами:

```json
{
  "sender": {"provider": "google_drive", "label": "Выбранная папка отправителя", "access": "manual"},
  "recipient": {"provider": "yandex_disk", "label": "Выбранная папка получателя", "access": "manual"},
  "copy_mode": "user_copy"
}
```

Для `shared_folder` требуются одинаковый провайдер и полный ID ресурса, `verified` с доказательством проверки на обеих сторонах, право `write` у отправителя и `read` у получателя. Файл в чате не выдаётся за общую папку.

После любого способа передачи получатель отдельно проверяет состав и целостность пакета. Затем идут согласование импорта и применение памяти — сохранение файла в облаке само по себе их не выполняет.
