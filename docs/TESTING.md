# Проверки версии 0.7.0

Дата: 20 ноября 2026. Среда фактического прогона: Windows, Python 3.12.14. Все данные вымышленные; реальные аккаунты и личные архивы не использовались.

## Кто проверяет

Разработчик запускает автоматические тесты, демонстрационный перенос и проверки сборок. Независимый агент проверяет логику и воспроизводит пользовательский сценарий по инструкциям навыков. Пользователь участвует в оценке удобства диалога и в согласовании собственных данных; он не обязан вручную тестировать каждую функцию программы.

После размещения в GitHub конфигурация `.github/workflows/tests.yml` будет запускать тесты на Windows и Linux с Python 3.10 и 3.12. Это подготовленная конфигурация, а не уже пройденный облачный прогон.

## Нужны ли личные аккаунты

Для проверки кода, диалога и развилок аккаунты SaaS не нужны: используются вымышленные записи, локальные файлы и явно смоделированные возможности.

Для проверки запуска именно в браузерном агенте нужен доступ к соответствующему веб-аккаунту. Это может быть аккаунт для тестирования; если используется обычный аккаунт, достаточно отдельного разговора и вымышленных файлов. Выгружать всю личную историю для такой проверки не требуется. Успех в тестовом аккаунте не доказывает, что в другом аккаунте доступны те же инструменты: тариф и настройки организации могут отличаться.

Проверка дискового подключения — отдельный интеграционный шаг: нужен реальный подключённый сервис, но достаточно папки с вымышленными материалами. В итерации 0.5 почтовое наблюдение и фоновое ожидание остаются отложенными. Проверка в настоящем рабочем аккаунте нужна, если требуется подтвердить работу именно в его конфигурации.

## Что ещё не проверено

Живая установка и запуск в веб-аккаунтах Claude/ChatGPT, инструменты ГигаАгента, реальное получение писем, авторизованное скачивание, запись в Google Drive и сохранение в постоянную память SaaS. Тест исполняемого кода внутри распакованного навыка не подменяет эти проверки.

Следующий приёмочный прогон: открыть два выбранных веб-агента, использовать вымышленные данные, установить навык либо загрузить ручной комплект, пройти цикл с реальными доступными инструментами и проверить результат чтением обратно. Сценарий описан в [WEB_SETUP.md](WEB_SETUP.md). Личные данные можно использовать после проверки этого цикла.

Текущая версия — проверенное локально ядро и подготовленные навыки для пилота, а не заявление о готовой интеграции со всеми SaaS.

Маршрут [CLOUD_DELIVERY.md](CLOUD_DELIVERY.md) реализован и проверен над локальными копиями: пользователь переносит готовую версию папки, затем получатель проверяет полный состав и продолжает настройку. Это не подтверждает реальную публикацию в каждом облаке или нативную настройку каждого агента: эти проверки требуют выбранных сред и их фактических инструментов.
